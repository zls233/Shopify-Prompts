# 使用 Shopify CLI 和 Admin GraphQL 导入商品

开始本任务前，先执行或复核 `01-project/1-2-建站授权准备.md`。必须确认用户自己的 Shopify Partner 账户已获得目标店铺 Partner / Collaborator 权限。若项目从未完成本 Prompt、目标店铺或执行身份已变化、令牌过期，或实际 scopes 不足，先补齐授权并验证，再进行商品写入；已有有效授权时直接复用。不得使用原店铺账号导入商品。

你需要把已经通过 CSV 清洗的商品数据导入目标 Shopify 店铺。本 Prompt 只负责商品写入和最小的结果核验；商品分类、自动 Collections、Menus、Metaobjects、Pages 和 Articles 使用各自的 Prompt 完成。

核心原则：批量导入优先，验证与发布分阶段进行。不要把每个商品的发布、图片 `READY` 等待和完整深度核验放进导入循环，除非样本或失败重试明确需要。

同时遵循 `EXECUTION_RULES.md` 的全量完成条件。样本通过后直接继续已授权的全量导入，不能把几个首页商品或“脚本已写好”作为任务完成。恢复任务时先确认输入文件、store、身份和已验证的 handle，不重复创建或重新覆盖整批成功商品。

### 商品 ACTIVE 与库存 9999（用户明确指定的默认值）

> **商品默认值（2026-10-29）：** 当前用户要求目标 Shopify 店铺**所有已有及新建商品一律 ACTIVE**，所有可跟踪库存 Variant 在已核实的履约/销售 Location 的 `available` 绝对值为 **9999**。全量分页读回后方可验收；不把历史源站库存改写为 9999，不做 +9999 增量，不在未经核实的多地点重复设置库存。不可追踪项说明原因，Online Store publication 与 Live Theme 独立授权。详见 `STAGE_COMPLETION_CONTRACT.md`。

- CSV 默认 `Status=active`；目标店铺内已有 `DRAFT`、`ARCHIVED` 等商品也纳入状态差集，按已有授权范围统一转为 `ACTIVE`。已 ACTIVE 跳过，重复执行幂等，不能把现有商品回退为 DRAFT。
- 所有可管理库存的变体逐个读取库存 Item ID、tracking、实际 Location、available。使用当前 Shopify API 的**绝对库存设置**操作将该地点 available 设置为 9999，并在 mutation 后按 Item/Location 读回。不可对所有地点重复设置 9999，不可做累加。
- 如果库存不可跟踪或变体为非库存商品，列出具体 `not_applicable` 依据；需要启用 tracking 时先验证不会破坏该店履约设置。其他无法设置的项目记为 blocked、保留差集。
- 本用户已经将 ACTIVE/9999 指定为默认建站要求，不再把“手动添加 `--set-status ACTIVE`”作为先决条件。只更改需要的商品状态和库存字段，不因本要求覆盖已有商品的价格/变体/图片等无关数据。
- 商品 `ACTIVE` 与 Online Store publication 独立；发布渠道和 Live Theme 不自动改变。

## 开始前核对

1. 明确用户自己的 Partner 账户、目标 `{{SHOPIFY_STORE}}`、执行 App 身份、Admin API 版本和最终 CSV 文件路径。不要依赖脚本默认店铺、旧 `.env` 或当前浏览器标签。
2. 读取 CSV 清洗审计，记录商品数、变体数、唯一 SKU、图片数、重复 SKU、缺失字段和修复版路径。区分最终数据、样例、修复版及以前运行的产物。
   建立 `expectedHandles`、每个商品的预期 variants/媒体和有依据的 `excludedHandles`。未支持的原生商品功能列为 `blocked`，未经用户明确选择不得改成普通商品来凑足数量。
3. 运行 `01-project/1-2-建站授权准备.md` 选定路径的连接检查，确认同一执行身份实际具备商品写入能力。CLI 登录成功、TOML 声明和 deploy 成功都不能代替实际授权；缺少权限时按该 Prompt 补齐并重新验证。
4. 以 `Handle` 作为幂等主键，必要时以 SKU 辅助审计。先读取现有 Handle 数量和目标范围，明确哪些商品会创建、更新、跳过；不要因为网络中断就重复创建。
5. 在写入前输出一份 dry-run 计划，包括 Partner 账户、目标店铺、应用身份、CSV、商品/变体/图片数量、预计批次和是否允许发布。
6. dry-run 必须列出所有已存在 Handle 的 currentStatus / targetStatus=ACTIVE / statusAction，以及 InventoryItem + Location 的当前数量、目标 9999 和差值；发现 ACTIVE→DRAFT、未知库存地点或可能覆盖非目标地点时先修正计划。

## 导入阶段

1. 先用少量、具有真实变体和多张图片的商品验证 CSV 映射、价格、SKU、图片 URL 和 Handle。样本通过后再开始全量任务。
2. 优先使用 Shopify Bulk Operation 或一次请求包含多个 `productSet` 的批量 GraphQL。批量输入使用 JSONL/变量文件或项目已有的等价机制；不要为每个商品单独启动一次 CLI 进程。
3. 写入 mutation 的返回字段保持最小，只返回 Handle、商品 ID、操作状态和 `userErrors`。不要在每个商品的写入响应中请求完整的变体、媒体和 publication 列表。
4. 用稳定 Handle 实现创建或更新，保留脚本已有的状态文件、批次清单和审计文件。每个批次记录开始时间、结束时间、数量、成功数、失败数和失败 Handle。
   检查点同时绑定输入版本/哈希、store、App 身份和操作 ID；输入或目标改变时先对账，不将另一店铺或旧快照的成功标记复用。
5. 只重试短暂网络、限流或 5xx 错误。重试前先按 Handle 查询目标商品，确认上一次请求没有已经写入；权限、字段校验、SKU 冲突和 GraphQL `userErrors` 不要原样重试。
6. 每批检查 HTTP 状态、GraphQL 顶层 `errors`、mutation `userErrors` 和节流信息。不得以命令退出码或“请求已发送”作为成功依据。
7. 导入时无需逐商品等待媒体 READY，也不逐个发布到 Online Store。完成数据写入后在**同一阶段**批量设置和全量读回商品 ACTIVE 与库存 9999，不留给用户下一条指令；媒体与渠道发布单独处理。

## 导入后核验

1. 导入操作完成后，先做一次汇总查询：目标商品数、创建/更新/跳过/失败数、变体总数、SKU 缺失或重复数，以及商品 Handle 是否都存在。
   必须分页读回全部范围内 handle、variant 标识/选项和媒体关联，并与输入清单逐项对账；总数匹配不能证明成员与规格正确。下面的代表性深度核验用于补充，不能代替完整清单覆盖。
2. 先对目标全店所有商品状态和可跟踪 InventoryItem/Location 数量完成分页读回，保存不一致及不适用清单。再对少量代表性商品做深度核验，至少覆盖：单变体商品、多变体商品、多图片商品、含折扣价格商品和本次失败重试商品。检查变体数量、SKU、价格、图片数量和商品状态。
3. 对媒体只记录 Shopify 返回的数量和处理状态；不要让完整媒体 READY 等待阻塞商品写入。对 `PROCESSING` 项保存清单，稍后单独轮询或复核。
   交付前单独处理未完成/失败媒体；写入结束但媒体仍未就绪时，报告“数据已写入，媒体验收未完成”，不要报告图片全部正常。
4. 如果本次明确要求发布，再单独执行批量 publication 操作，并核对 Online Store publication。商品 `ACTIVE` 不代表已经发布到 Online Store；发布前确认 `write_products`、`write_publications` 和实际 publication ID。发布脚本必须默认 dry-run，使用显式 `--apply` 才能写入，并在写入后读回商品 `status`、Handle/GID 及 Online Store publication 状态。
5. 若导入中断，先读取状态文件和远端汇总结果，再从未完成或明确失败的 Handle 继续。不要删除商品或无条件重跑全量。

## 最终报告

报告以下内容：目标店铺、执行应用身份、API 版本、CSV 版本与清洗结果、计划/批次/创建/更新/跳过/失败数量、汇总核验结果、深度核验样本、媒体 `PROCESSING` 项、发布状态（如执行）和审计文件位置。

同时报告完整输入清单的 `expected / verified / missing / failed / blocked / excluded`，列出每个未解决 handle、原因和恢复命令。范围内项全部写入并读回后才报告全量导入完成；只导入样本、失败未处理、特殊商品静默跳过或原生功能不支持时，明确为部分完成。更新项目记忆和输入数据的重建/交接入口，避免迁移或干净 checkout 后导入脚本失去数据。

不要输出 token、密码或 client secret；不要在本任务中顺带改动 Collections、Menus、Metaobjects、Pages、Articles 或 Live Theme。
