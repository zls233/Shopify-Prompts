# 使用 Shopify CLI 和 Admin GraphQL 导入商品

开始本任务前，先执行或复核 `00-project/建站授权准备.md`。若项目从未完成该 Prompt、目标店铺或执行身份已变化、令牌过期，或实际 scopes 不足，先补齐授权并验证，再进行商品写入；已有有效授权时直接复用。

你现在需要把已经验证的商品 CSV 数据导入目标 Shopify 店铺，并核对商品、变体、SKU、价格和媒体的远端结果。本任务只负责商品导入；商品分类、自动 Collections、Menus 和 Metaobjects 使用 `03-catalog/创建分类.md` 单独完成。

## 开始前核对

1. 明确目标 `{{SHOPIFY_STORE}}`、执行 App 身份、Admin API 版本和最终 CSV 文件路径。不要依赖脚本默认店铺、旧 `.env` 或当前浏览器标签。
2. 列出 CSV 的商品、变体、唯一 SKU、图片数量和校验错误。区分最终数据、样例、修复版及以前运行的产物；不重复导入已经存在的商品。
3. 运行 `00-project/建站授权准备.md` 选定路径的连接检查，确认同一执行身份实际具备商品写入能力。CLI 登录成功、TOML 声明和 deploy 成功都不能代替实际授权；缺少权限时按该 Prompt 补齐并重新验证。
4. 检查现有商品的 handle 和 SKU，确定创建、更新、跳过的数量，保留不应覆盖的字段。

## 导入

1. 先用少量商品验证 CSV 映射、变体、图片和价格，再执行全量导入。
2. 使用 Shopify CLI 执行受支持的店铺操作，并以 Admin GraphQL 完成商品写入与核验。不要假设 CLI 存在直接导入商品 CSV 的命令；先检查当前 CLI 的命令及限制。`shopify app execute` 的 mutation 仅适用于开发店。正式店写入时，确认所用 CLI 命令或项目应用的 Admin GraphQL 客户端具有正确的应用身份；使用 `shopify store auth` / `shopify store execute` 前尤其要核对身份。
3. 用稳定 handle / SKU 实现可恢复的创建或更新。分批写入，记录进度与每批结果。只重试短暂网络、限流或服务端错误；重试前查询上一批是否已经成功。
4. 对每次响应检查 HTTP 状态、GraphQL 顶层 `errors`、mutation 的 `userErrors` 和节流信息。不得以命令退出码为唯一成功依据。

## 远端验收

重新查询目标店铺，核对商品、变体、唯一 SKU、状态、价格、媒体数量与媒体处理状态，并列出缺失或失败项。商品 `ACTIVE` 不代表已经发布到 Online Store；若本次任务还包含发布，应另外核对 `write_publications` 和实际 publication 状态。

最后报告：目标店铺、执行应用身份、CSV 版本与校验结果、创建/更新/跳过数量、远端核对结果、失败与可重试项、审计文件位置。不要输出 token、密码或 client secret；不要在本任务中顺带改动 Collections、Menus、Metaobjects 或 Live Theme。
