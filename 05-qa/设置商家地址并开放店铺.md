# 设置商家地址并开放 Shopify 店铺

将下面的 Prompt 复制给 AI 编程工具，替换 `{{...}}` 变量。仅在店主明确要求开放店铺时关闭 Private Mode；这会使当前 **Live Theme** 对无需密码的访客可见。

## 输入

- 目标店铺：`{{SHOPIFY_STORE}}`，填写准确的 `*.myshopify.com` 域名。
- 商家地址：`{{BUSINESS_NAME}}`、`{{FIRST_NAME}}`、`{{LAST_NAME}}`、`{{ADDRESS_LINE_1}}`、`{{ADDRESS_LINE_2_OPTIONAL}}`、`{{CITY}}`、`{{STATE_CODE}}`、`{{POSTAL_CODE}}`、`{{COUNTRY_CODE}}`、`{{PHONE_OPTIONAL}}`。
- 本次任务：`{{UPDATE_BUSINESS_ADDRESS}}`、`{{DISABLE_PRIVATE_MODE}}`。分别填写“是”或“否”。
- Admin API 版本：`{{ADMIN_API_VERSION}}`，执行时选择当前受支持的稳定版本。
- 项目目录：`{{PROJECT_PATH}}`。

## Prompt

请直接完成上述店铺设置，并核验实际结果，不要只提供操作步骤。

1. 读取项目 `AGENTS.md` 和现有授权说明；以我明确提供的 `{{SHOPIFY_STORE}}` 为目标。如果变量尚未填写，先问清准确域名，不要从 `.env`、历史报告或已打开的 Admin 标签推定目标店铺。区分 **Settings → General 的商家地址**、发货地点、账单地址、支付账户资料和客户地址；这次只修改我指定的商家地址。不要把姓名、电话、邮箱、地址、令牌或密码写入仓库、审计文件、命令 URL 或截图。
2. 优先使用 Shopify CLI 做只读盘点。通过已有的 `shopify store auth` 授权，运行带 `--store {{SHOPIFY_STORE}}` 和固定 Admin API 版本的 `shopify store execute`，读回 `shop.myshopifyDomain`、`shop.shopAddress`、`onlineStore.passwordProtection.enabled`、`currentAppInstallation.app` 和实际 `accessScopes`。确认返回店铺与输入完全一致。检查当前 Live Theme 和 Online Store 发布状态；不要把 Draft Theme 预览当成公开首页。
3. 查当前 Shopify 官方文档与 Admin GraphQL schema，确定这两项设置是否有受支持的 mutation。不要把读取字段误认为可写接口，也不要用 `shopify app execute` 对生产店铺尝试 mutation。若没有相应受支持接口，使用项目规定的**已登录 SunBrowser** 操作 Shopify Admin；不要切换浏览器身份或擅自启动新的账号登录。
4. 如果 `{{UPDATE_BUSINESS_ADDRESS}}` 为“是”，进入 Shopify Admin 的商家地址表单，逐项填写提供的姓名、街道、城市、州、省、邮编、国家和电话。`N/A` 或空白的地址第二行保持空白。不要擅自勾选“registered business”、修改 Shopify Payments 或将用户邮箱填入其他用途的字段。保存后从 Admin 页面及 Admin GraphQL `shop.shopAddress` 读回，逐字段核对；如果出现订阅方案、付款或法律条款确认，先说明具体要求，不要替我购买或接受协议。
5. 如果 `{{DISABLE_PRIVATE_MODE}}` 为“是”，先核对这是我明确指定的店铺，并说明关闭后当前 Live Theme 将向公众开放。如电脑操作规则要求对公开访问变更在执行时再次确认，按规则取得确认后，在 **Online Store → Preferences / Store access** 关闭 Private Mode 并保存。不要改动密码值或把密码保存在浏览器中；不要顺带更改 B2B 限制、SEO、主题发布或其他设置。
6. 保存后再执行一次带 `--store {{SHOPIFY_STORE}}` 的 CLI 只读查询。对本次实际修改的项目，分别确认地址字段匹配、`onlineStore.passwordProtection.enabled` 为 `false`。若本次关闭了 Private Mode，以未带密码、无管理员登录态的 HTTP 请求访问 `https://{{SHOPIFY_STORE}}/`，确认最终 URL 未落在 `/password`、响应正常、页面不是密码表单。必要时再用无痕/独立浏览器验证；不要用已登录 Admin 的预览作为唯一证据。
7. 如果是批量或结构性操作，按项目规则保存不含个人信息的机器可读审计；单次店铺设置只需在回复中记录店铺、App 身份、操作、核验结果和时间。说明哪些输入字段没有对应表单字段、哪些内容未改。区分“密码保护关闭”和“商品、导航、结账已达到上线质量”；如公开页面仍有问题，列出具体问题和下一步。

推荐的只读核验查询（执行时使用明确的 `--store` 和 API 版本；不要将原始含个人信息的响应写入仓库）：

```bash
shopify store execute --store {{SHOPIFY_STORE}} --version {{ADMIN_API_VERSION}} --json --query 'query VerifyStoreAccess { shop { myshopifyDomain shopAddress { address1 address2 city provinceCode countryCodeV2 zip phone } } onlineStore { passwordProtection { enabled } } currentAppInstallation { app { apiKey title } accessScopes { handle } } }'
```

若 Shopify CLI 授权缺失，先核对店铺和 App 身份，再按项目既定流程运行 `shopify store auth --store {{SHOPIFY_STORE}} --scopes <所需权限>`；不要把 Theme Access token 当作 Admin GraphQL 凭据。若只读查询因 scope 不足失败，不要把该失败解释为店铺仍处于 Private Mode；可从 Admin 界面和公开请求分别核验，并明确记录 API 核验限制。

参考：[Shopify CLI store execute](https://shopify.dev/docs/api/shopify-cli/store/store-execute)、[ShopAddress](https://shopify.dev/docs/api/admin-graphql/latest/objects/ShopAddress)、[OnlineStorePasswordProtection](https://shopify.dev/docs/api/admin-graphql/latest/objects/OnlineStorePasswordProtection)、[Shopify 帮助：管理店铺访问](https://help.shopify.com/en/manual/online-store/themes/password-page)。
