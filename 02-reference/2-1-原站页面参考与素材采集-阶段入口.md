# 2-1｜原站页面参考与素材采集（默认完整高保真阶段）

> 必读 `STAGE_COMPLETION_CONTRACT.md` v3 与 `VISUAL_FIDELITY_STANDARD.md`。FAST 只减少重复采集，**不得省略范围内完整视频、精细动画、全部可见区块、精确素材、响应式或离线参考可复查性**；不必等待用户另说 FULL。优先复用与当前源站版本相同、可信、足够完整的现有 reference。

## 目标和范围

以 `05-customization/5-2-功能削减.md` 决定实际要复刻的页面：Home、有效 Header/导航、PLP、PDP、Cart、相关浮层与交互。Footer 采用统一固定八链接，不复制原站复杂 Footer。不得采集源站 Checkout/支付/订单确认页面。不同模板及不同视觉/交互的有效 Section 均需覆盖，不能因为已有“代表性首页”而漏掉中下部区块。

## 默认必做

**导航/链接必交接**：按 `NAVIGATION_LINK_GATE.md` 逐状态采集桌面/手机 Header、Products/Mega Menu（所有层级）、搜索/Cart、首页 CTA、各分类卡片与保留的 Footer 入口。维护 `references/navigation-link-map.json`（source href、标签、层级、触发/设备状态、预期目标 Shopify 类型/URL、证据、解析状态）；没有展开态截图/DOM 和目标映射，不得让 4-1 假定顶栏是一排平铺链接。


1. **页面与状态索引**：列出范围内全部模板/区块及链接，记录源 URL/时间/设备/版本；检查已有 DOM、截图、HTML、素材和交互资料，逐项标记缺口。
2. **完整截图与样式**：Desktop 1440×900、Mobile 390×844 同时保留全页及关键分区；记录首屏、中部、底部、交互展开状态、滚动 sticky 前后、真实断点及 320/375/768 等需要补验的尺寸。采集 DOM/HTML、字体/computed style、尺寸、对齐、文字换行、图像比例与裁切、颜色、间距、层级。
3. **完整范围内媒体**：为每个可见视频/背景视频保存或可靠定位源文件、poster、时长、编解码、可见区域、autoplay/muted/loop/playsinline 和实际播放表现；保存每个有效 Section 的真实图片、mobile 版本、svg/logo/favicon、字体与 SHA/MIME/尺寸。不得用截图代替视频或用占位资源冒充 matched。
4. **动效与交互**：逐项记录 dropdown、hover、carousel、tabs、accordion、sticky、scroll/lazy-load、变体/图集等初始态/触发/时长/延迟/easing/终态、键盘和触屏行为；视频的初始/播放/暂停状态与条件一并记录。未知参数标 `unknown` 并取证，不能猜值。
5. **可离线核验的参考档案**：保存对应 HTML/DOM 快照、图片/字体/视频与海报、截图和 manifest；实测主要离线页面/媒体的打开或解码。外部脚本/DRM/API 不允许完整动态回放时留替代证据并明确 `blocked`，不假装离线回放一致。
6. **完整交接**：更新 `references/manifest.json` 或现有等价文件，包含 section/source/state/media/animation/responsive/mapping/status/evidence；将商品 URL、分类入口交给 3-1，将视觉/素材差异与覆盖矩阵交给 4-1。保存失败清单和恢复命令，停止对同一防护的无效重复请求。

## 完成标准

只有范围内全部可执行页面/区块、Desktop/Mobile、原站媒体/视频、关键与细致动画、响应式差异和可复查参考已核验，才报告 `completed_full`。任何实际要复刻的中下部、视频、精细动画、离线素材/证据缺口均为 `partial`，真实不可解决的权限/源站阻断为 `blocked_core`。**禁止以“4-1 可以先继续”“功能不影响购买”为由降为 P2 或提前 `completed_core`**。已明确排除的页面/功能保持 excluded。

所需素材只从已获授权范围内使用；不绕过访问控制。无需写冗长报告，只给出覆盖数量、关键缺口、取证路径和状态。

## 2-1 批处理与 Token 优化（2026-11-06）

1. 先建立**显式范围清单**（模板 × Desktop/Mobile × 菜单/轮播/变体/搜索/滚动等状态）；按授权和页面范围填写 `reference-plan.json`，不无界爬取、不得绕过防护。参考 `Shopify-Template/scripts/reference-capture.mjs` 及 `examples/reference-plan.json`。该工具负责基础页面/状态的重复性截图与 DOM 提取，**不是**完成高保真参考的唯一依据。
2. **样本门禁**：仅选一个代表性页面完成 Desktop/Mobile 截图、静态 DOM、字体/图片/视频资源记录与离线回放校验；确认完整依赖、路径和文件可读，才批量采集。避免先采几十页再返工补 CSS/字体。
3. 相同来源、URL 和版本的媒体只下载一次；使用 `reference:media` 生成 hash/MIME/尺寸/失败清单，按资源类型限并发与字节量。大文件不回显到模型，也不把无必要的大型二进制直接纳入普通 Git 历史；必要时用 Git LFS/独立归档，保证可复查。
4. 所有 Playwright、网络、离线取证脚本只输出本次总数、差集、失败原因和文件路径；原始 HTML、完整 DOM、图片/视频、trace 存磁盘。对同根因网络故障最多两种**有变化**的恢复策略；403/验证码立即记录并停止该支线。
5. 脚本完成后仍按本阶段原规则逐一核对缺失 Section、真实动画/视频状态、全部有效导航层级、离线重放和断点差异。证据不全则 `partial`，不能为省 Token 减少采集范围。
