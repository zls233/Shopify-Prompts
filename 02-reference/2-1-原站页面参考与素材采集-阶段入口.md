# 2-1｜原站页面参考与素材采集（FAST 完整阶段）

> 默认 FAST 必须先阅读 `STAGE_COMPLETION_CONTRACT.md`；该文件定义核心完成/P0-P2/省 Token/断点和授权。此入口**仅使用下述精简流程**。旧版详尽的页面样式/检查维度已迁移到 `archive/full-guidance/`，只有用户显式 FULL、像素级验收或遇到未解决的专项问题时才按需读取对应段落；不在 FAST 首轮全量读取归档。实际项目的 `PROJECT_MEMORY.md` 和已保存检查点优先，目标 Store/Theme 必须以现时真实资料为准。

## 核心交付（P0/P1）

目标是获取**足以开发**当前 Shopify 核心页面的可用参考。不要把源站全部网页爬下来，也不要把离线视觉完美回放设为门槛。

1. **复用**：检查已有 `references/`、`manifest.json`、源站快照和输入版本。无变化且可用的内容继续用，不重复下载。确定 Home、代表性 PLP、代表性 PDP、Cart 的模板列表；同类型不同页面只有实质布局/交互差异才额外采样。
2. **采集**：对每种模板获取可用的 HTML/DOM（或原始可核实资料）、Desktop 1440 和 Mobile 390 的主要截图及关键区域信息。记录 Header/Mega Menu、导航目标、商品卡/图集与变体、响应式差异、实际主图/Hover 图顺序、关键互动。截图主要覆盖首屏/商品购买区/尾部必要信息，缺资料再补。不得取证原站 Checkout、支付资料或订单确认页面。
3. **素材**：保存真实 Header 品牌主 Logo 与 favicon 的**独立**来源，优先 SVG/PNG/ICO 等可解码资产；必要时为 Logo 留文字/字形证据供 3-1 做独立图。不得用菜单推广图、banner、商品首图或 favicon 假冒品牌支付 Logo。保存来源 URL、相对路径、文件/MIME/尺寸、SHA 与可信状态；找不到时记录准确源站障碍，不假造 verified。
4. **交接**：生成一个精简 `references/manifest.json` 或复用同等 manifest，记录页面/素材路径、源 URL、采集时刻、模板种类、浏览器有效性、缺口。把已发现的商品入口/分类 URL 交 4-1，而不是在 2-1 把全部商品详情再抓一遍。
5. **停止条件**：每个核心模板至少一个可用参考且移动/桌面明显结构可辨、关键素材/导航信息有证据时，报告 `completed_core`。原站禁止访问、缺少独立 Logo/fav 时保留准确 `deferred/blocked` 记录，不把未取得内容说成可用；只有确实无法识别核心模板、会阻塞后续主题开发才标 `partial/blocked_core`。

## FAST 省时间

- 优先已有响应和公开允许接口。访问受限时停止自动请求，不使用换 IP/身份/Cookie 绕过防护。
- SingleFile 离线渲染、像素级回放、所有交互状态、超多断点和整站媒体归档是增强项，按需做，不作为 FAST `completed_core` 前提。
- 不默认写长篇逐页面报告、生成重复截图、反复恢复失联浏览器。脚本生成单份摘要与失败清单。
- 一次精简成果报告：模板覆盖、截图/素材路径、可用性、后续 4-1/3-1 交接、精确缺口。用户显式 FULL 时按 `archive/full-guidance/reference-capture-detailed.md` 增强范围。

## 当前范围边界

遵循 `05-customization/5-2-功能削减.md`：固定免邮公告仅 UI 文案，Footer 固定八个信息链接，不复刻原站 Footer；FAQ/Blog/Stores 等独立页面默认不需要；Cart 与真实 Checkout 入口保留，但本阶段不进入源站 Checkout。没有这些页面不阻止核心阶段完成。
