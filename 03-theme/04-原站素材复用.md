# 复用原站素材完成 Shopify Theme 复刻

请直接完成主题素材复用和验证，不要只提供方案或伪代码。

本 Prompt 用于把目标原站已经使用的视频、图片、文本、图案、SVG、图标和其他矢量素材，准确映射到当前 Shopify Theme。目标是保持原站的真实内容和视觉身份，不用生成内容或通用占位素材替代已有原站素材。

## 输入

执行前确认以下变量：

```text
TARGET_SITE_NAME={{TARGET_SITE_NAME}}
TARGET_SITE_URL={{TARGET_SITE_URL}}
PROJECT_PATH={{PROJECT_PATH}}
REFERENCE_PATH={{REFERENCE_PATH}}
SHOPIFY_STORE={{SHOPIFY_STORE}}
DRAFT_THEME_ID={{DRAFT_THEME_ID}}
SOURCE_OBSERVED_AT={{SOURCE_OBSERVED_AT}}
```

`TARGET_SITE_NAME`、`TARGET_SITE_URL` 和 `PROJECT_PATH` 是本次任务的唯一目标信息来源。不要从旧报告、`.env`、浏览器标签或示例值猜测原站、店铺或 Theme ID。若目标站点或项目路径为空，先停下来确认。

## 目标

将原站素材逐项复用到 Shopify Theme：

* 视频使用原站视频文件或原站公开 CDN 地址
* 图片使用原站实际图片或已保存的原站文件
* 文本保留原站原文、语言、大小写、标点和换行意图
* 图案使用原站实际纹理、重复背景、遮罩或装饰资源
* SVG、Logo、图标和其他矢量图保留原始路径、`viewBox`、颜色和比例
* Desktop 与 Mobile 使用原站对应的素材变体和裁切方式

如果原站已有可确认的素材，不得用 AI 生成图、库存图、渐变、纯 CSS 几何图形、通用图标、虚构文案或灰色占位图代替。找不到原站素材时，记录具体缺失项和证据，不要默默换素材。

## 一、开始前读取项目和素材证据

1. 读取项目 `AGENTS.md`、`PROJECT_MEMORY.md`（如存在）、主题 README、`manifest.json`、`site-reference-summary.md` 和 `{{REFERENCE_PATH}}` 下的采集文件。
2. 检查 Git 状态、当前分支、目标店铺和目标 Draft Theme。任何 Shopify 主题操作前运行：

   ```bash
   shopify theme list --store {{SHOPIFY_STORE}} --json
   ```

   从本次返回中确认店铺域名、当前 Live Theme、`{{DRAFT_THEME_ID}}` 的角色和 `processing` 状态。默认只推送到明确的 unpublished Draft，不发布或修改 Live。
3. 记录 reference 的采集时间和本次原站观察时间 `{{SOURCE_OBSERVED_AT}}`。归档文件和当前原站冲突时，说明采用哪个版本以及原因，不要把历史素材当成当前事实。
4. 先建立素材清单，不要直接开始写 CSS。至少覆盖首页、Header、Footer、集合页、商品卡、PDP、内容页和移动端中实际出现的素材。

## 二、建立原站素材清单和映射表

为每个素材保留一行记录，字段至少包括：

```text
页面/区块
素材类型（video/image/text/pattern/svg/icon/vector）
原站 URL 或 reference 文件
文件格式 / MIME
原始尺寸 / viewBox / 时长
Desktop / Mobile 变体
原站 alt 或可见文本
Shopify 目标文件或 Section setting
使用方式（asset_url/image_picker/video_url/native text）
哈希或稳定识别信息
状态（matched/missing/blocked）
证据和备注
```

素材查找顺序：

1. 已保存的 WebArchive、SingleFile、HTML、截图、`manifest.json` 和下载文件。
2. 原站当前 DOM、`src`、`srcset`、`poster`、CSS `background-image`、SVG 内联内容和 Network 请求。
3. 原站公开 CDN 上与页面实际引用相同的文件。

不要只从截图猜图片 URL。对于视频，确认真实 `source`、编码、时长、poster、自动播放、静音、循环和 `playsinline`；对于响应式图片，记录每个断点实际使用的文件。

## 三、素材实现规则

### 视频

优先复用原站视频 URL 或已保存的原始视频文件，并保留原站的：

```text
autoplay
muted
loop
playsinline
preload
poster
object-fit
object-position
```

视频必须有静态 poster 或无视频时的原站图片回退。不要把视频截图当成最终视频，也不要用 CSS 动画冒充原站视频。远程视频请求失败时记录失败原因和回退状态。

### 图片

使用原站原图及对应的 Desktop / Mobile 版本。保留原始宽高比、裁切、`object-position`、加载策略和显示顺序。图片应通过当前主题合理的 `asset_url`、`image_picker`、Section setting 或原站稳定公开 URL 接入；不要为了方便把一组图片硬编码成另一套假数据。

### 文本

从原站 DOM 或已保存页面中复制实际文本，保持：

```text
语言
大小写
标点
空格
换行
标题层级
CTA 文案
alt 文本
```

不要翻译、润色、缩写、补写或改成品牌相似文案。原站文本属于 Shopify 商品、Collection、Page、Blog 或 Article 时，优先绑定真实 Shopify 对象；不要用静态假卡片伪装成真实目录内容。

### 图案、SVG 和矢量素材

优先保存并复用原始 SVG 或矢量文件，保留 `viewBox`、`preserveAspectRatio`、路径、填充、描边、遮罩、渐变和透明度。不要把可复用 SVG 随意 rasterize，也不要用手绘近似图案替代原始资源。必须清理时，只移除明确的跟踪、编辑器元数据或无关脚本，不改变视觉路径和尺寸。

不要复制原站的分析、广告、聊天、账号、支付或其他第三方运行脚本；本 Prompt 只复用页面呈现所需的媒体和内容。

## 四、接入 Shopify Theme

1. 将需要随主题交付的本地素材放在当前主题合理的 `assets/` 或现有资源目录，并在素材清单中记录来源和哈希。不要把临时截图、缓存、浏览器 profile 或无关大文件带入主题。
2. Section 使用 `section.settings`、`section.blocks`、`image_picker`、`video_url`、`collection`、`product`、`page` 和 `url` 等现有主题模式，让后台仍可替换已确认的素材。
3. 复用原站素材不等于绕过 Shopify 数据边界：首页真实商品、Collection、Page、Blog 和 Article 必须使用实际 Shopify 对象、handle、GID、发布状态和原生 URL；缺失数据单独记录为阻塞。
4. 保留原站素材在 Section 中的顺序、比例、层级和响应式关系。不要因为 Shopify 实现方便而合并独立区块、改写文案或改变 CTA 目标。
5. 对缺少 Shopify 资源的 CTA，先报告缺少的 handle/GID 或页面，不要 fallback 到首页，也不要用无效的 `href="#"`。

## 五、验证

完成实现后，按以下顺序验证：

1. 静态检查：`npm run check`、JSON 解析、变更 JavaScript 的 `node --check` 和 `git diff --check`。
2. 主题检查：运行 `shopify theme check --path theme`；若工具挂起或不可用，记录阻塞，不得把未运行报告成通过。
3. Draft Theme 上传：使用明确的 `--store`、`--theme`、`--nodelete`；未经授权不要加 `--allow-live`。
4. 浏览器对比：在至少 `1440px` 桌面和 `390x844` 移动端打开原站与 Draft，检查同一滚动位置的素材、文本、裁切、比例、层级和交互。
5. 检查实际 DOM 和 Network：确认视频、图片、SVG 和字体请求指向素材清单中的资源；没有 404、错误 MIME、意外占位图或未加载的关键媒体。
6. 对 Header、Hero、商品卡、Footer 和移动端菜单分别截取证据。确认原站文案逐字一致、素材变体正确、页面无横向溢出；控制台中的 Shopify 预览噪音与主题运行错误分开记录。

## 六、完成报告

报告必须区分以下结果：

* 素材清单中已匹配、缺失和阻塞的数量
* 实际复用的视频、图片、文本、图案、SVG/矢量文件及其目标 Section
* Theme 文件和 Shopify 资源的变更
* Draft 上传、远端文件回读和浏览器对比结果
* Live 是否修改（默认为否）
* 未验证的商品、内容、导航或外部资源限制
* 可复现的下一步命令和仍需用户提供的素材/授权

不要只报告“页面已完成”或“上传成功”。远端文件一致、Shopify 资源状态和公开 storefront 呈现必须分别给出证据。
