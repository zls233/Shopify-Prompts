# Cookie 提示

为站点实现首次访问时出现在页面下方的 Cookie 弹窗，提供“接受所有 Cookie”和“仅接受必要 Cookie”两个清晰按钮。优先参考已采集的 WebArchive、截图及原站移动端样式；没有可靠样式证据时沿用当前主题视觉系统。

两个按钮都应关闭弹窗，并分别在 `localStorage` 保存用户选择；刷新后不重复弹出。此阶段只实现可见 UI 和选择记忆，不实现追踪脚本拦截或完整 CMP。不要声称它提供了实际的非必要 Cookie 控制。

验证首次访问、两种按钮、刷新持久化、桌面和移动端布局、键盘可达性，以及弹窗不会遮挡加入购物车等核心操作。对移动端首次访问要检查提示高度、页面滚动和核心按钮的可点击性；对本地存储不可用的情形应允许本次会话关闭提示。保留轻量浏览器核验记录和两种视口截图，不创建或运行测试套件，除非用户明确要求。不要使用浏览器默认 `alert`。

默认只在指定 Draft Theme 实现和验证。若用户随后明确要求只把本组件推送 Live，先重新读取目标店铺当前 Live ID，拉回并核对涉及的 snippet、layout、CSS、JS 与线上差异；仅对批准的文件使用 `--allow-live --nodelete` 和逐文件 `--only`。推送后读回 Theme 角色、拉回文件逐字节比对，并在公开首页及受影响页面的桌面/移动端重新检查两种选择和刷新持久化。不能将 Draft 截图、CLI 上传成功或文件哈希相同当作公开生效的唯一证据；也不能把本地存储选择称为 CMP 或实际追踪拦截。
