## FAST 6-1 必查：商品卡片优惠 Badge 一致性

在实际目标 Draft 的 Desktop/Mobile 中覆盖首页、Collection/PLP、搜索和推荐/相关商品（实际存在的区域），检查折扣商品均有常显且统一的醒目 Badge，无折扣商品不出现虚假标签；核对百分比是否与当前价格及 Compare At Price 相符，并覆盖不同折扣率、规格切换和无优惠样例。

检查 Hover、图片切换、快速加购、售罄标识、响应式布局的叠加和遮挡。不能只验一个首页样本、只确认 CSS 存在或只确认商品价格已更新；发现部分模板缺标签、折扣百分比错误或样式不一致，在已授权 Draft 中修复后复验。详细规则见 `EXECUTION_RULES.md`。

## 品牌 Logo / 第三方支付交接验收（FAST 6-1 必查）

- 单独核对 `references/_shared/branding/checkout-logo-source.json`、主题独立 Logo 资源与 `docs/payment-branding-handoff.md`；与实际 Header 品牌标志比对内容、比例、透明背景，确认**不是 favicon、菜单促销图（如 `menu-travel.jpg`）、商品图或 banner**。不能只看 Header 上有品牌文字，就宣称支付页有可用 Logo 图片。
- 检查图像格式/MIME、有效 SVG viewBox 或位图尺寸、SHA-256；确认文件实际在本项目已验证的 Theme asset 或 Shopify Files 中，且交接文档带上当前 store、最新目标 Theme 角色、托管方式及**准确绝对 HTTPS URL**。可公网访问时实测 HTTP 200、图片可解码、内容正确和浅色底可识别；受 Draft/密码限制未能公网核验时记 `pending_live_url`，发布后再做 URL 回读，不使用旧 Theme ID 拼接地址。
- 给主题素材交接与第三方页面展示**分开状态**：`asset_handoff: verified / failed / blocked`；`checkout_logo_display: verified / failed / blocked / not_run / excluded`。第三方尚未接入时，后者为 `not_run`，**不因支付端未上线而将主题交付判失败**；但是 Logo 文件缺失、拿错图或交接信息不完整属于主题侧缺陷，需修复。
- 如果第三方结账已接入，按 `06-qa/6-4-购物车与结账入口测试.md` 的安全边界验证实显 Logo；发现 `store_logo` 为空/指错图，记录差异并将正确 URL 交付支付接入方，不默认改写其代理脚本或支付设置。将以上状态、证据和责任方记入 `PROJECT_MEMORY.md` 与交付报告。
