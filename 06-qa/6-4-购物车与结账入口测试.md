# 购物车 → 结账入口冒烟测试（最终 QA）

你现在的任务：在当前 Shopify 店铺完成**真实浏览器购物链路冒烟测试**：

**商品详情页 → 选择可售规格 → 添加到购物车 → 打开购物车 → 点击 Checkout/结账 → 成功进入本项目配置的结账界面。**

本测试只验证进入结账界面，不测试支付，也不创建订单。**不再复刻参考网站的结账页面、支付表单或订单确认页面**；它们由项目独立的支付系统处理。必须保留真实有效的购物车 Checkout 按钮，不能使用空链接或假的结账页面。

## 前置与测试范围

1. 读取 `EXECUTION_RULES.md`、`05-customization/5-2-功能削减.md` 以及当前项目 `PROJECT_MEMORY.md`。确认目标 store、实际 Live Theme ID/角色、商品 Online Store 发布状态、店铺是否处于 Private Mode，避免误测其他项目。
2. 项目输入：目标店铺 `{{SHOPIFY_STORE}}`；测试首页 `{{STOREFRONT_URL}}`；预期结账目的地 `{{EXPECTED_CHECKOUT_DESTINATION}}`（应来自项目实际配置，不能从参考站猜测）。可以是 Shopify 原生 Checkout，也可以是**本项目获授权、实际配置的自有结账系统**。未确定预期落点时必须说明，不能宣称自有支付系统已接入。
3. 优先在**已发布、公开可访问的 Live 店铺**用独立无管理员登录态的浏览器测试。仅 Draft 预览可测时状态为 `preview_only`，不能代替 Live 通过。使用 Playwright 或现有浏览器均可；不得只检查代码、模拟点击或 HTTP 200。
4. 此 Prompt 授权实际点击 Add to Cart 和 Checkout 并查看结账页面，**不授权填写姓名/地址/银行卡资料、付款、确认订单或修改支付配置**。不对参考网站进行购买行为。

## 真实浏览器测试步骤

1. **进入真实 PDP**：从首页或 Collection 进入一个已发布、正常标价、有库存的真实商品，不用 Gift Card、零价异常商品或测试占位商品。选择真实可售 Variant；如果有 Color/Size，实际切换并记录商品 Handle、Variant ID（可取得时）、售价及币种。
2. **加入购物车**：点击 Add to Cart，确认请求成功且页面购物车状态更新。有 Cart Drawer 时展开并按正常路径进入 Cart，不能只用按钮文字或 JS 返回值判断成功。
3. **核对 Cart**：购物车必须显示刚添加的正确 Product/Variant、颜色、尺码、数量、商品图片、单价、折扣与币种，且与 Shopify 的真实售价一致；Checkout/结账按钮可见、可点击，没有阻断弹窗或前端错误。
4. **点击 Checkout**：在 Cart 内实际点击结账按钮，等待导航或新标签页加载。验证最终确实出现**本项目预期的结账界面**：核对实际 host/path 与已批准的结账目的地一致，有可见的结账步骤或表单容器，非 404/5xx、密码页、空白页、死循环或其他品牌结账页面。**仅 URL 含 `checkout` 或得到 200 不算通过**。
5. **立即停止**：结账界面确认可见后就停止。不输入任何个人或支付信息，不确认支付，不下单；若进入未知第三方域名、非授权目标，立即停止并报告失败/阻塞。
6. **分别测 Desktop 与 Mobile**：至少用 `1440px` 与 `390px` 两个 viewport 各走一次完整链路，测试之间使用独立或清理后的购物车，检查移动端 Cart/Checkout 入口可点击。

## 成功与失败判断

只有两个 viewport 都实测「真实可售商品成功加购 → Cart 明细正确 → 点击 Cart Checkout → 进入本项目已确认的真实结账页面」，才标记 `passed`。如果进入了 Shopify 默认结账页，但项目要求自有支付系统且未集成，**不得**报告自有支付集成通过。任何阻断项为 `failed`；因访问、权限、结账配置或浏览器不可用而无法验证为 `blocked`；没有实际运行则为 `not_run`。

出现问题，逐步定位 PDP 加购、Cart 数据、Checkout 按钮、导航、实际结账页面或目的地不匹配。仅在现有权限范围内定向修复 Theme 交互并复测；不得顺带变更支付系统/Shopify 支付配置或将源站结账页面纳入复刻。
