你现在的任务不是继续搭建页面结构，而是对当前 Shopify Theme 做一轮“像素级视觉校准”，目标是让当前页面在相同 viewport 下尽可能 1:1 匹配源网站。

源网站：
使用当前任务中已经提供、已经浏览或已经归档的目标源网站。

当前 Shopify 预览站：
使用当前已经连接的 Shopify Theme Dev / Preview 环境。

把这次任务视为 visual regression 修复，而不是 UI 设计任务。源网站就是唯一视觉基准，不要自行“优化”设计，也不要用主观审美替代源站实际尺寸。

当前状态：
- 页面整体结构已经基本正确
- Hero 区域、导航、公告栏等主要模块已经存在
- 但视觉细节与源站仍有明显偏差
- 目前不要重构整个页面，也不要重新开始
- 应该在现有实现基础上做精细调整

重点问题包括但不限于：

1. Header / Navigation

顶栏通常由多层组成，请以源站实际结构为准逐层识别。

对于当前页面：

- 顶部 announcement bar 在滚动后可以离开视口
- announcement bar 下方的主 Header 和主导航栏在向下滚动时应该继续保留在页面顶部
- 当前实现需要严格复现源站实际滚动行为

重点检查：

- sticky / fixed 行为
- sticky 生效时机
- sticky top offset
- 各层之间的相对位置
- header 高度
- border
- background
- z-index
- shadow
- 滚动前后布局是否跳动
- sticky 后是否产生额外空白
- sticky 后内容是否被覆盖

优先将需要保留的 Header 区域作为一个整体 sticky group 处理，而不是随意给多个子元素分别设置 sticky，除非源站本身就是这种行为。

2. Header 尺寸精度

逐项对比并校准：

- announcement bar 高度
- 主 Header 高度
- 主导航高度
- 搜索框宽度
- 搜索框高度
- 搜索框圆角
- 搜索框左右位置
- logo 实际显示尺寸
- logo 上下位置
- logo 与其他元素的间距
- 右侧入口文字的位置
- account / help / cart 等图标尺寸
- icon stroke 粗细
- 图标之间 gap
- 导航项字号
- 导航项字重
- letter-spacing
- 导航 item 间距
- header 左右 padding
- divider 的位置和厚度

不要只看整体相似度，要检查各元素实际 bounding box。

3. Hero 区域

当前 Hero 与源站在视觉比例上仍可能存在明显误差。

必须对比：

- Hero 总高度
- Hero 宽度
- 左右区域实际宽度比例
- 图片区域比例
- 左侧图片裁切方式
- 右侧图片裁切方式
- object-fit
- object-position
- background-size
- background-position
- 图片是否基于 viewport 自适应
- Hero 顶部与导航栏的连接位置
- Hero 底部结束位置
- Hero 是否有 min-height / max-height
- 图片原始宽高比与当前显示宽高比

不要只保证图片内容相似，要保证裁切后的可见区域与源站尽量一致。

尤其要观察：

- 人物距离左右边缘的位置
- 图片主体距离顶部的位置
- 背景中特征物体的位置
- 两张图片分界线的位置

这些都可以作为视觉定位参照物。

- 按钮字体

- button border

如果源站在同样 viewport 下显示两行，当前页面也应该尽量在同一个单词位置换行。

5. Typography

不允许继续用“看起来差不多”的方式处理。

请检查源站实际 computed style，包括：

- font-family
- font-weight
- font-size
- line-height
- letter-spacing
- text-transform
- font-style

如果源站加载了自定义字体：

- 优先识别源站实际字体
- 检查当前 Theme 是否已有对应字体资源
- 检查源站页面归档、Network、CSS、font-face
- 如果当前项目里已有可用字体资源，正确接入
- 如果没有，再选择最接近的已有字体
- 不要未经检查直接使用系统默认字体

字体差异往往会进一步导致：

- 元素宽度不同
- 导航间距不同
- 标题换行不同
- 按钮尺寸不同

因此字体需要较早校准。

- flex-basis
- row-gap

特别注意：

很多视觉误差并不是某个子元素自身尺寸错误，而是父级容器的：

- padding
- height
- gap
- flex alignment
- grid width
- max-width

不准确导致的。

优先修正父级几何关系，再微调子元素。

8. Responsive behavior

当前优先完成桌面端，但实现时不要写死到单一屏幕尺寸。

主要验收：

- 当前浏览器实际 viewport
- 1440px 左右的 desktop viewport

如果源站在不同宽度下使用 breakpoint：

- 识别源站 breakpoint
- 按源站逻辑实现
- 不要简单使用一组固定 px 值撑所有宽度

允许使用 px，因为像素级复刻本身需要精确尺寸，但这些值应来自对源站的实际测量，而不是猜测。

5. Hero 左右分栏比例基本一致

7. Hero 文案位置基本一致
8. 标题字号、行高、换行位置基本一致

10. 搜索框、Logo、图标等 Header 元素尺度基本一致

最终判断依据不是“功能是否实现”，而是在相同 viewport 下两张截图的视觉差异。
