# Shopify 商品列表页复刻与校准

你现在需要继续完善当前 Shopify Theme 的商品列表页（Collection / Search Product Listing Page）。

目标不是做一个通用电商商品网格，而是根据当前项目中的 reference、目标网站实际页面和 Shopify 店铺中的真实商品数据，逐项校准商品列表页的结构、视觉、内容和交互行为，尽可能做到与原页面 1:1 对齐。

本 Prompt 适用于：

- Collection 页面，例如 `/collections/{{COLLECTION_HANDLE}}`
- 搜索结果页，例如 `/search?q={{SEARCH_QUERY}}`
- 原站以商品列表为核心的分类、专题或结果页面

如果当前任务只涉及 Collection 页面，不要顺带修改商品详情页、首页、Live Theme 或无关 Shopify 资源。

## 目标信息

执行前填写：

```text
TARGET_SITE_NAME={{TARGET_SITE_NAME}}
TARGET_SITE_URL={{TARGET_SITE_URL}}
TARGET_COLLECTION_PATHS={{TARGET_COLLECTION_PATHS}}
TARGET_SEARCH_PATHS={{TARGET_SEARCH_PATHS}}
DRAFT_THEME_ID={{DRAFT_THEME_ID}}
```

以上变量是本任务的目标信息来源。不得把示例站名、域名、Collection handle 或 Theme ID 写死进代码。

## 执行约束

1. 开始前读取 `04-customization/功能削减.md`，不重新加入已明确削减的功能。
2. 明确目标店铺、当前 unpublished Draft Theme 和 Live Theme 的真实 ID/角色。未经明确授权，不发布或修改 Live Theme。
3. 涉及商品、Collection、publication、菜单或 metafield 时，先核对当前 App 身份和实际权限；不要使用历史报告、旧 `.env` 或浏览器当前标签代替实时读回。
4. 如果工作区已有未提交修改，不得 reset、checkout、clean 或覆盖无关文件；只修改本任务相关文件。
5. 优先复用现有 product card、filter、pagination、header、footer、drawer、CSS 和 JavaScript。不要为了列表页单独维护一套重复商品卡。
6. 不要使用静态假商品、写死商品名称/价格/图片 URL、标题过滤商品，或把所有链接 fallback 到首页。

## 一、先审计 reference 与现状

不要直接开始改 CSS。先分别审计：

```text
原站商品列表页 / reference
当前 Shopify 商品列表页
当前 Shopify 商品、Collection、publication 和排序结果
```

检查并记录：

- 页面类型、URL、Collection handle 或搜索参数
- 采集日期与当前原站观察日期，记录版本差异
- Header、breadcrumb、页面标题、描述、banner 和分类导航
- 商品总数、每页数量、默认排序和分页方式
- Desktop / Mobile 的列数、卡片宽度、间距、图片比例和容器宽度
- 筛选器的分组、选项、计数、展开方式、drawer、URL 参数和清除行为
- 排序菜单的选项、默认值、选中状态和 URL 行为
- Product card 的图片、hover 图、badge、标题、副标题、价格、compare-at price、swatch、库存和 CTA
- quick add、quick view、wishlist、hover 操作及键盘/触摸行为
- merchandising card、推广横幅、插入式内容卡和空状态
- loading、分页、load more、错误状态、无结果状态和返回位置

建立差异表，至少分成：

```text
Theme 结构 / Liquid 渲染
CSS / 响应式布局
JavaScript / URL 与交互
Shopify 商品、Collection、排序、筛选与 publication
媒体资源与外部加载
reference 中存在但当前项目明确排除的功能
```

不能因为网格能渲染、HTTP 返回 200 或循环输出了商品，就宣称商品列表页完成。

## 二、真实 Shopify 数据与资源核对

列表页必须由 Shopify 原生对象驱动，优先使用：

```liquid
collection
collection.products
collection.filters
collection.sort_options
collection.sort_by
paginate collection.products
product
product.options_with_values
product.selected_or_first_available_variant
product.featured_media
product.media
```

执行前核对：

1. Collection 是否真实存在、规则是否正确、商品数量是否与预期一致。
2. 商品是否 `ACTIVE` 且已发布到 Online Store；`ACTIVE` 不等于已发布。
3. 默认排序是否与原站一致，不能仅凭 Liquid 输出顺序猜测。
4. 筛选字段是否来自真实 `collection.filters`，不要伪造不存在的品牌、价格、颜色或尺寸选项。
5. 商品标题、价格、compare-at price、库存状态、图片和 URL 是否来自当前商品数据。
6. 缺失的商品字段保持为空或按主题安全隐藏；不要臆造卖点、折扣、评分、库存或评论。
7. 外部 reference 中的商品若尚未导入或未发布，记录为资源阻塞，并按对应商品/分类工作流处理，不用假卡片填空。
8. 对照原站采集时的商品数量与当前 Shopify 数量，抽查应命中和不应命中的商品；若 New Arrivals 等集合混入旧折扣品，先核对商品标签与自动 Collection 规则，不用 CSS、Liquid 标题匹配或前端过滤掩盖差异。
9. 原站的分类子导航和 Category / Material / Color 等 facets 只有在当前 Menu、Collection filters 或商品字段真实提供时才能展示；缺失时记录所需资源及责任层，不伪造筛选选项。

## 三、页面结构与商品网格

按原站实际结构实现，不要套用默认 Collection 模板。重点校准：

- 页面最大宽度、左右 gutter、顶部间距和 breadcrumb
- 标题、描述、banner、分类入口和商品数量的位置
- 工具栏布局、筛选按钮、排序菜单和移动端控制区
- Desktop、tablet、mobile 的列数和断点
- 商品卡片宽度、列间距、行间距和列表尾部留白
- 网格在 0、1、2、3 个商品以及最后一行不完整时的布局稳定性
- 画面加载时的 skeleton 或占位行为，不得导致卡片尺寸跳动

商品卡必须是独立可复用 snippet，例如：

```text
snippets/product-card.liquid
```

列表页应传入真实 product 和必要的上下文，不要把商品数据复制到页面 Liquid 中。卡片至少校准：

```text
主图与 hover 图
图片 aspect-ratio / object-fit / object-position
badge 与促销状态
标题、副标题和品牌信息
现价、划线价、货币格式
颜色/尺寸 swatch
库存或售罄状态
商品链接和可访问名称
```

商品卡的图片、标题、价格和 CTA 必须指向当前真实商品。禁止使用 `href="#"`、`javascript:void(0)`、空 href 或错误地全部指向首页。

## 四、筛选、排序与 URL 状态

如果原站有筛选或排序，必须先还原实际行为，再决定使用 Shopify 原生机制还是现有主题封装：

- 使用真实 `collection.filters` 和 `collection.sort_options`
- 支持多选、单选、价格区间、清除单项和清除全部（以原站为准）
- 桌面端侧栏/顶部栏与移动端 drawer 的状态一致
- 选项选中态、结果数量、禁用态和无结果状态准确
- URL query 参数可复制、刷新后可恢复，并且浏览器后退/前进行为正确
- 排序切换后保留或清除筛选条件，按原站实际行为处理
- 不用 JavaScript 标题匹配、CSS 隐藏商品或前端硬编码选项伪造筛选

如果当前主题已有筛选组件，先修复其数据和状态边界，不要重复实现第二套组件。筛选器不能遮挡页面内容，drawer 打开时要处理滚动锁定、关闭按钮、Escape 和触摸关闭。

## 五、分页、Load More 与加载状态

根据 reference 实际行为实现分页或 Load More：

- 使用 Shopify `paginate` 或现有主题的稳定实现
- 页码、下一页、上一页和当前状态可访问
- Load More 不重复商品、不丢失筛选/排序参数，并更新 URL 或按原站行为处理
- 加载失败可重试，空结果和末页有明确状态
- 切换筛选或排序后清除旧列表状态，避免重复和错位
- 不因预加载全部商品而破坏 Shopify 分页、性能或商品 publication 边界

## 六、响应式与交互 QA

至少在以下尺寸检查原站与 Draft：

```text
Desktop: 1440x1200
Mobile: 390x844
```

必要时补充 tablet 和更窄手机宽度。用 Playwright 或现有浏览器工具核对：

```text
boundingBox
font-size / font-weight / line-height
margin / padding / gap
grid columns / card width / image height
filter drawer / sort menu / pagination
image loading / broken image
keyboard focus / Escape / touch behavior
```

重点验证：

- 商品卡标题、价格和 badge 不重叠或溢出
- 图片比例稳定，hover 图不会改变卡片高度
- 筛选 drawer、排序菜单和 sticky 工具栏不遮挡商品内容
- 移动端不会横向滚动，按钮和输入区域可操作
- 商品链接、筛选 URL、排序 URL 和分页 URL 都返回预期页面
- 无结果、售罄、缺图、缺价格和商品数量不足时页面仍然可用

## 七、实现与同步边界

只在确认差异归属后修改对应层：

```text
Liquid / JSON template / section
product-card snippet
CSS
JavaScript
真实 Shopify 商品或 Collection 数据
```

不要用 CSS 遮掩数据错误，不要把内容资源问题伪装成主题问题。默认只同步到指定 Draft Theme，并重新读取 Draft 实际输出。用户明确要求“推送 Live”时，先区分“只同步已 QA 的文件”与“切换 Live Theme”：前者仅限本任务文件，重新读取当前 Live ID，拉回同名文件检查差异，再使用 `--allow-live --nodelete` 和逐文件 `--only`；后者需要独立的主题发布授权，不得由“推送”二字推定。文件推送后再次读取 Live 角色、拉回逐字节比对，并在公开页面复查 1440px / 390px 的列表、搜索 URL、排序/筛选/分页和溢出。文件已上线不等于商品分类、价格或交付状态合格。

## 最终报告

报告以下内容：

- 目标店铺、Draft Theme ID、Live Theme ID/角色
- 参考页面与采集/观察日期
- 实现或修改的模板、section、snippet、CSS、JavaScript 文件
- Collection / 搜索路径、商品数量、默认排序和筛选资源核验结果
- Desktop / Mobile 的实际 QA 尺寸与结果
- 商品卡、筛选、排序、分页和 URL 状态的完成情况
- 缺失商品、未发布商品、媒体或权限阻塞
- Live 是否仍未修改、已限定文件同步或已另行授权切换主题；列出文件、远端读回和公开页面验证结果，以及尚未解决的资源问题

不要输出 token、密码或 client secret；不要把静态截图、HTTP 200、Theme Check 通过或“商品循环成功”当作完整完成证据。
