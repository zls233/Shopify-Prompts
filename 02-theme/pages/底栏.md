你现在的任务是：**基于当前已有 Shopify Theme、现有 reference 文件以及目标原站，完整完善当前页面的 Footer / 底栏，使其在结构、视觉、内容和响应式表现上尽可能与原站一致。**

不要重新设计 Footer，也不要凭印象补一个“类似”的 Footer。
必须优先读取当前项目中已经采集的 reference，并结合原站实际页面进行对照。

---

## 目标

完善当前 Shopify Theme 中已有的 Footer，实现以下结果：

* Footer 整体结构与原站一致
* 栏目数量、分组方式、标题、链接排列与原站一致
* 字体、字号、字重、颜色、行高、间距、边距、分割线、背景色、图标尺寸等尽量 1:1 对齐
* Desktop 与 Mobile 均正确适配
* 原站 Footer 中可以直接跳转的外部链接，应实现真实跳转
* 原站 Footer 中对应站内页面、但当前 Shopify 店铺尚未实现的页面，可以暂时保留正确的链接结构或合理占位，后续再实现对应页面
* 不得为了让链接“看起来可用”而错误地全部指向首页或 `#`

---

## 明确排除的内容

以下内容本项目不需要实现。

如果原站 Footer 中存在，请直接删除、隐藏或不要复刻：

* Account / My Account / 账号管理
* Login / Sign in / 登录
* Register / Sign up / 注册
* 在线聊天 / Live Chat
* 客服聊天组件
* Gift Card / 礼品卡
* Bundle / Bundled Purchase / 捆绑购买相关入口
* Email Newsletter
* 邮件订阅表单
* Email Signup
* Subscribe / Join our mailing list
* Footer 中任何为了收集邮箱而存在的输入框、按钮、弹窗或组件

注意：

普通的帮助中心、FAQ、Shipping、Returns、Warranty、Contact、Stores 等普通信息页面，**不要因为属于 Customer Service 分类就误删**。

这里排除的是“在线聊天和相关聊天组件”，不是删除整个帮助类导航。

---

## 第一步：分析现状

先检查当前项目中的 Footer 实现，包括但不限于：

* `sections/`
* `snippets/`
* `assets/`
* `layout/theme.liquid`
* Footer 相关 Liquid
* Footer 相关 CSS
* Footer 相关 JavaScript
* 当前菜单配置或硬编码导航

同时读取项目中已经存在的 reference，例如：

* `site-reference-summary.md`
* `manifest.json`
* `references/`
* Desktop 截图
* Mobile 截图
* SingleFile / HTML
* 已采集的原站页面

然后实际打开目标原站，对 Footer 做一次完整检查。

不要只看首页最底部的一张截图。

需要确认：

* Footer 从什么位置开始
* Footer 上方是否存在独立的 USP / Service / Guarantee 区域
* Footer 主体有几列
* 每列标题
* 每列链接
* Social links
* Country / Region / Currency selector
* Copyright
* Legal links
* Privacy
* Terms
* Accessibility
* Cookies
* Sitemap
* 外部平台链接
* App / Social / Corporate links
* Logo / Icon / Badge
* Desktop 与 Mobile 的差异
* Mobile 是否使用 accordion
* 是否存在 divider / border
* Footer 的最大宽度
* 左右 padding
* 上下 spacing
* 背景颜色
* 文本颜色
* hover / focus 状态

以原站当前实际表现为准，不要自行猜测。

---

## 第二步：建立 Footer 链接清单

在修改代码之前，先在内部整理 Footer 中的所有链接，并区分为以下几类：

### A. 可以现在直接实现的外部链接

例如：

* Instagram
* Facebook
* TikTok
* YouTube
* Pinterest
* LinkedIn
* Corporate site
* 第三方政策页
* 其他明确指向站外的 URL

这类链接直接使用原站实际 URL。

需要：

* 正确 `href`
* 必要时 `target="_blank"`
* 添加合理的 `rel="noopener noreferrer"`

不要写 `#`。

---

### B. 当前 Shopify 中已经存在的内部页面

如果对应页面、collection 或资源已经存在，则直接链接到实际 Shopify URL。

优先使用 Shopify 对象 URL，例如：

```liquid
{{ pages.xxx.url }}
{{ collections.xxx.url }}
{{ routes.xxx_url }}
```

如果当前项目已有统一 URL 处理方式，则延续现有模式。

---

### C. 原站存在，但当前 Shopify 尚未实现的页面

这类页面后续还会继续实现。

不要为了临时通过测试而：

* 全部跳首页
* 使用 JavaScript 阻止跳转
* 写成错误页面
* 删除整个导航项

应尽量保留与原站信息架构一致的目标路径。

例如可以暂时使用：

```text
/pages/returns
/pages/warranty
/pages/accessibility
/pages/sustainability
/pages/stores
```

具体 handle 必须结合当前项目已有命名和原站 URL 结构决定。

如果已有页面命名规范，必须保持一致。

---

### D. 明确排除的功能

对于：

* Account
* Login
* Register
* Gift Card
* Newsletter
* Email signup
* Live Chat
* Bundle

直接不实现，不需要保留占位链接。

---

## 第三步：完整实现 Footer

基于分析结果修改现有 Footer。

优先修改已有组件，不要无必要新建一整套重复 Footer。

要求覆盖：

### 1. Layout

准确处理：

* Footer 宽度
* max-width
* 左右 gutter
* column 数量
* grid / flex 布局
* column gap
* row gap
* 顶部和底部 padding
* section 间距
* divider
* copyright 区域

避免出现“结构差不多，但整体尺寸差很多”的情况。

---

### 2. Typography

逐项对照原站：

* Footer heading font-size
* font-family
* font-weight
* letter-spacing
* text-transform
* link font-size
* line-height
* copyright 字号
* Legal link 字号
* Mobile 字号

不要统一使用一个字号解决所有 Footer 文本。

---

### 3. Links

所有 Footer link 都必须具备正常交互。

包括：

* hover
* focus-visible
* keyboard navigation

不要留下：

```html
href="#"
```

除非 reference 明确证明原站本身就是这样，并且当前没有更合理的目标。

---

### 4. Social Icons

如果原站存在 Social Icons：

* 保留实际存在的平台
* 使用与项目现有图标体系一致的 SVG / snippet
* 尺寸、间距、颜色对齐原站
* 正确跳转至原站实际社交媒体 URL

不要使用 emoji 或 Unicode 字符模拟图标。

---

### 5. Mobile Footer

必须单独验证 Mobile。

如果原站 Mobile Footer 使用 accordion，则实现对应 accordion，而不是简单把 desktop grid 压成一列。

Accordion 需要：

* 初始状态正确
* 点击可展开 / 收起
* icon 状态同步
* keyboard 可操作
* 不出现布局跳动异常

如果原站并非 accordion，则不要擅自加入 accordion。

---

### 6. Footer Bottom Bar

完整处理原站 Footer 最下方区域，例如：

* Copyright
* Privacy
* Terms
* Accessibility
* Cookie 设置
* Sitemap
* Country / Region
* Currency
* 其他 Legal links

但需要继续遵守前述“不实现账号、聊天、Gift Card、Newsletter”等限制。

---

## 第四步：不要写死不应该写死的数据

如果 Footer 中存在适合 Shopify 动态化的内容，优先动态化。

例如：

```liquid
{{ shop.name }}
{{ 'now' | date: '%Y' }}
```

菜单如果当前 Theme 已经通过 Shopify Navigation 管理，则尽量继续使用 Navigation。

但不要为了“动态化”破坏原站结构。

对于原站固定存在、且当前项目确实需要严格还原的 Footer 内容，可以保留在 section schema 或配置中。

---

## 第五步：与原站做视觉校准

完成第一轮后，必须实际运行主题并用浏览器进行对比。

分别检查：

### Desktop

建议至少：

```text
1440px
```

重点检查：

* Footer 起始位置
* 总高度
* 每列宽度
* column gap
* heading 位置
* link 间距
* divider
* social icon
* bottom bar
* 左右边距

### Mobile

建议至少：

```text
390px
```

重点检查：

* 水平 padding
* accordion / section 排列
* link 行高
* section 间距
* icon 位置
* Legal links 换行
* Copyright
* 是否发生横向溢出

不要只依赖肉眼看代码。

使用 Playwright、浏览器或当前项目已有的 browser/computer-use 能力进行真实页面验证。

---

## 第六步：检查链接

Footer 完成以后，对所有 Footer `<a>` 做一次检查。

确保不存在：

* 明显错误 URL
* `javascript:void(0)`
* 无意义的 `#`
* 本应外链但链接到 Shopify 首页
* 本应内部页面却误跳原站
* 账号、注册、Gift Card、Newsletter 等被排除内容残留

对于尚未实现的站内页面，可以保留规划好的 Shopify path，但需要记录出来。

---

## 第七步：最终验收

完成修改后执行项目已有的检查流程。

至少包括：

```bash
shopify theme check
```

如果项目已有其他 lint / validation，也一并执行。

然后再次进行 Desktop + Mobile 浏览器验证。

---

## 完成后输出

不要只回复“已经完成”。

最后给我一个简洁报告，包括：

1. 修改了哪些文件
2. Footer 实现了哪些区域
3. 哪些外部链接已经真实可跳转
4. 哪些内部链接对应页面尚未实现
5. 哪些原站 Footer 功能因为本项目要求被移除
6. Desktop / Mobile 是否完成实际浏览器验证
7. `shopify theme check` 结果
8. 仍然存在的差异或待实现页面

---

## 最重要的执行原则

不要重新设计 Footer。

不要为了快速完成而做一个通用 Shopify Footer。

不要只看截图大概模仿。

**以当前已有主题为基础，以 reference + 原站当前 Footer 为唯一视觉和结构基准，逐项对照并实际修改到接近 1:1。**

本轮只负责 Footer 本身。

对于 Footer 中指向但尚未实现的内部页面，只建立正确的链接结构并记录，**不要在本轮顺手实现那些页面。**
