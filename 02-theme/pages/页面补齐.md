# Shopify 内容页面批量补齐与原站复刻

开始创建或更新 Pages / Blogs / Articles 等 Shopify 资源前，先执行或复核 `00-project/建站授权准备.md`。确认目标店铺、执行应用身份与真实 `write_content` 能力；若完整建站权限包已获批，则直接复用，不要每次重新申请。

## 用途

用于在 Shopify 主题已经完成主体结构、Header / Footer 和基础样式后，继续批量补齐 Footer、导航或其他入口中已经预留，但目标店铺尚未实际创建的内容页面。

适用于：

- Help / Service 页面
- Brand / About 页面
- FAQ
- Size Guide
- Store Locator 入口页
- Blog / Guide 列表页
- Shipping / Returns / Warranty / Product Care 等内容页

目标不是只创建“能打开”的页面，而是完成：

**原站审计 → Shopify Resource 创建 → 模板实现 → 原站视觉复刻 → 响应式适配 → Draft Theme 同步 → 浏览器 QA**

# 当前任务

继续完善当前 Shopify 项目，将 `{{TARGET_PATHS}}` 中尚未实现的路径全部补齐。

这些页面需要：

1. 在 Shopify 中真实存在。
2. 可以通过对应 URL 正常访问。
3. 尽可能还原 `{{TARGET_SITE_NAME}}` 原站对应页面。
4. 正确适配 Desktop 和 Mobile。
5. 与现有 Header、Footer、Cookie、导航和主题样式兼容。
6. 最终只同步到 Draft Theme `{{DRAFT_THEME_ID}}`。
7. 不得发布、修改或覆盖 Live Theme。

# 一、执行约束

## 功能削减约束

执行前读取 `04-customization/功能削减.md`，并将其作为项目功能削减范围的唯一权威清单。页面、模板、导航和页面内 CTA 均不得重新加入清单中的功能入口、组件或占位；不得只用 CSS 隐藏入口，也不得删除无关 Shopify 商品或店铺资源。普通静态帮助内容（如 Shipping、Returns、Warranty、FAQ、Contact）不因属于客服/帮助分类而自动排除，仍按本任务要求补齐并链接到真实页面。具体排除范围只在权威清单维护，本文不另行复制完整清单。

必须遵守：

- 优先使用 Shopify CLI。
- 如果 CLI 无法完成，优先使用 Shopify Admin API。
- 缺少权限时，先按 `00-project/建站授权准备.md` 申请完整建站权限包；仅做独立内容任务时申请该任务所需权限。
- 只有 CLI / API 无法完成的操作，才使用浏览器自动化或 Computer Use。
- 不得因为缺少页面就把链接临时改到首页。
- 不得使用 `#`、`javascript:void(0)`、空 `href` 等方式伪装完成。
- 不允许创建大量写死 HTML 来绕过 Shopify Resource。
- 不允许把所有页面简单套入一个 Generic Template 后宣告完成。
- 优先复用现有 section、snippet、CSS 和 JavaScript。
- 不破坏已经完成的 Header、Footer、导航、Cookie、Collection、Product 等现有功能。
- 不修改 Live Theme。

如果当前 Git 工作区已有未提交内容：

- 不得 reset、checkout、clean 或覆盖其他人的改动。
- 仅修改与本任务相关文件。

# 三、审计原站

以：

```text
{{TARGET_SITE_URL}}
```

作为页面复刻基准。

逐个找到 `{{TARGET_PATHS}}` 对应的真实原站页面。

不要只根据 handle 猜 URL。

优先通过：

1. 原站 Header / Footer
2. sitemap
3. 页面内部链接
4. Help Center
5. Blog index
6. 已有本地 reference
7. 搜索引擎仅作为补充

如果原站被 Cloudflare、WAF 或其他反爬机制阻止，依次尝试：

1. 本地 reference
2. 已采集 HTML / SingleFile / WebArchive
3. sitemap
4. 普通 HTTP
5. 当前浏览器会话
6. Playwright
7. Computer Use

不得因为一次 403 / 502 / connection closed 就停止整个任务。

# 七、页面类型实现原则

下面是常见页面的处理要求。

如果目标站的实际结构不同，以原站为准。

---

## Shipping / Returns

重点检查并复刻：

- Hero / Page title
- Shipping information
- Delivery
- Returns
- Refund
- Accordion
- Help CTA
- Policy links

不得自行编造：

- 配送时效
- 运费
- Return 时间
- Refund 时间
- 地区规则

必须以原站真实公开内容为准。

---

## Order Status

先确认原站真实功能。

如果原站存在订单查询：

优先使用目标 Shopify 店铺当前真实可用的订单追踪能力。

不得伪造订单结果。

允许：

- 真实 Shopify order-status 能力
- 官方 tracking 页面
- 合法可用的真实外部查询入口

禁止：

- 输入任意订单号都显示假物流
- 写死 tracking result
- 为了复刻重新加入 `04-customization/功能削减.md` 明确排除的功能

---

## Product Care

重点：

- Jewelry / Product care instructions
- Material-specific sections
- 图文区域
- Cards
- Accordion
- CTA

内容必须来源于目标原站或 reference。

---

## Warranty

实现真实静态 Warranty 内容。

不得自行修改：

- Warranty duration
- Warranty coverage
- Exclusion
- Claim procedure

---

## Size Guide

重点检查：

- Ring
- Bracelet
- Necklace
- Clothing / Shoe / Product-specific sizing
- Tables
- Tabs
- Accordion
- Measurement diagram
- Unit conversion

确保 Mobile 下表格和 Tabs 可正常使用。

---

## Gift Packaging

只实现包装说明页面本身。

不要因此重新实现：

- Gift Card
- Bundle
- Gift Card balance
- Gift Card purchase

---

## Accessibility

按照原站 Accessibility Statement 实现。

不要自行生成法律声明。

---

## About

不要只创建一个标题加几段 Rich Text。

根据原站真实结构实现：

- Hero
- Brand story
- Timeline
- Image/text
- CTA
- Editorial sections

---

## Sustainability

根据原站真实结构复刻：

- Hero
- Commitments
- Metrics
- Image / text
- Cards
- Reports
- CTA

不得自行编造环保数据。

---

## Craftsmanship

重点还原：

- Hero
- Storytelling
- Full-width imagery
- Editorial typography
- Alternating image/text
- Details
- CTA

## Stores

首先确认原站 Store 页面性质：

- Store locator
- Store information page

- Map
- Search form

优先使用当前可用的真实 locator 或外部 Store Locator。

不得伪造门店数据库。

如果无法复制其底层功能：

实现真实可访问的入口，并尽量保持原站视觉结构。

## FAQ

优先还原原站真实信息架构：

- Category

- Mouse

- focus visible
- Mobile

- Blog listing

- 虚构作者

优先自动化采集公开文章列表，再生成结构化数据进行批量创建。

目标不是“页面存在”。

目标是尽量接近原站。

逐项校准：

- section spacing
- Hero
- Typography
- H1 / H2 / body
- line-height
- letter-spacing
- CTA
- links
- divider
- card
- image ratio
- grid
- accordion
- table
- icons
- Desktop / Mobile

如果已有项目 CSS token：

优先复用。

不要为了一个页面加入大量互相冲突的 magic numbers。

# 十一、响应式 QA

至少测试：

```text
Desktop: 1440px
Mobile: 390px
```

必要时：

```text
Tablet: 768px
```

检查：

- 无 horizontal overflow
- Hero crop 正确
- Typography 正常
- 图片比例正确
- 内容顺序正确
- Accordion 正常
- Tabs 正常
- Table 可用
- CTA 不溢出
- Cards 正常换行
- Header 正常
- Footer 正常

Mobile 不得只是 Desktop 强制缩小。

---

# 十二、交互与可访问性

Accordion / Tabs / menu 等必须：

- Mouse 可操作
- Keyboard 可操作
- 状态同步
- focus visible
- 正确 ARIA

JavaScript 必须兼容 Shopify Theme Editor。

避免：

- 重复绑定 listener
- section reload 后失效
- 依赖固定唯一 DOM ID
- console error
- 全局污染

---

# 十三、项目排除项

以 `04-customization/功能削减.md` 为唯一权威清单。若原页面包含清单中的模块，不实现并移除其专属入口和组件，同时调整布局避免留下明显空洞。不要在本任务文档中复制排除项，以免不同任务的清单发生漂移。

# 十四、链接审计

# 二十一、执行方式

现在直接开始执行。

不要只输出建议、计划或待办列表后停止。

```text

→ 原站实测
```

最终目标：

**让所有目标内容页面在 Shopify 中真实存在、可以访问、结构正确、响应式正常，并且视觉与交互尽可能接近目标原站，同时保持现有主题功能稳定。**
