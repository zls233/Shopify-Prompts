你现在需要继续完善当前 Shopify Theme 的首页。

目标不是“做一个风格类似的首页”，而是：

**根据当前项目中的 reference 文件和目标网站原首页，对 Shopify 首页进行逐项校准，尽可能做到结构、视觉、内容组织和交互行为与原页面 1:1 对齐。**

参考来源包括：

* `site-reference-summary.md`
* `manifest.json`
* `references/`
* Desktop / Mobile 截图
* SingleFile / WebArchive / HTML
* 当前目标网站原首页
* 当前 Shopify Theme 已有实现

如果当前实现与 reference / 原网页冲突，以 reference 和原网页实际表现为准。

先读取 `04-customization/功能削减.md`；原站有而项目明确排除的模块不加入首页。确认参考的采集日期和当前原站观察日期，记录版本差异，避免把两个时期的内容混用。

执行前明确目标 store，并实时读取目标 unpublished Draft 和当前 Live 的 Theme ID/角色。涉及商品、集合、菜单或文章时，先核对当前 App 身份、权限和 Online Store publication；不要用历史报告中的 ID 或 `.env` 默认值替代实时读回。未经明确授权不发布或修改 Live。

---

先分析当前首页与 reference 的差异，不要直接盲目改 CSS。

建立逐区块的内容对照表，至少包含源站标题/文案/媒体/CTA/商品或文章样本、目标 Section 设置、目标资源 handle/GID/数量/规则/发布状态、Draft 实际输出和差异归属。将差异分成 Theme 布局/渲染、配置/菜单、Shopify 商品/价格/分类、Pages/Blogs/Articles、外部素材加载及项目明确排除项。先确认归属，再修改对应层；不要因为页面能渲染或 Section 顺序正确就宣称首页内容已对齐。

重点检查：

* Announcement bar
* Header
* Desktop / Mobile 导航
* Hero
* Banner
* Featured collections
* Featured products
* Category cards
* Promotional sections
* Image + text sections
* Video sections
* Brand / story sections
* Reviews / social proof
* Newsletter
* Footer
* Sticky 导航行为

确认原页面 Section 的顺序、尺寸、留白、背景、图片比例和交互。

---

## 视觉要求

重点校准：

* 页面最大宽度
* Section 上下间距
* 左右边距
* 字体
* 字号
* 字重
* 行高
* 标题宽度
* 图片尺寸
* 图片裁切方式
* Grid 列数
* 卡片宽度
* 卡片间距
* Button 尺寸
* Border
* Background
* Desktop / Mobile 布局

不要只做到“结构差不多”。

可以使用 Playwright 获取 source 和 Shopify 页面元素的：

```text
boundingBox
font-size
font-weight
line-height
margin
padding
gap
width
height
```

然后逐项校准。

---

## Hero

重点还原：

* Hero 高度
* 图片 / 视频
* Desktop / Mobile 不同素材
* 文案位置
* 标题宽度
* CTA 数量
* CTA 样式
* Overlay
* 文案对齐方式
* 页面顶部与 Header 的关系

如果原页面 Hero 使用视频，则优先按原页面方式实现。

不要为了截图效果使用大量 absolute positioning 硬拼。

---

## Section 必须动态化

不要把整个首页写死在 Liquid 里。

优先使用 Shopify Section + Blocks。

例如：

```text
Hero
Image banner
Featured collection
Featured products
Image with text
Promo grid
Video
Newsletter
```

应该尽量通过：

```text
section.settings
section.blocks
collection picker
product picker
image picker
video_url
page picker
url setting
```

进行管理。

不要把具体商品名、Collection handle、图片 URL 和 CTA URL 全部写死。

---

## Collection / Product 内容

如果首页展示商品或分类：

必须绑定真实 Shopify 数据。

优先使用：

```text
collection
products
product
```

不要使用静态假商品。

读取自动 Collection 的规则、数量、排序及正反样本，并对照源站可见商品；`ACTIVE` 不等于 Online Store 已发布。若集合把旧款或折扣商品放进 New Arrivals，先审计标签/规则/价格/发布状态，按数据工作流修复并读回，不要用 Liquid 标题过滤、手写商品列表或 CSS 遮掩。若 Blog 只有一篇而原站显示三篇，应核对真实 Articles 和发布日期；不能把一篇旧文重复成三张卡，也不能仅凭 Theme 正常循环就判定内容完成。资源修改不在本轮授权范围时明确列为未完成及下一步。

Collection 卡片和 Product 卡片应复用当前主题已有组件，避免首页单独维护另一套商品卡。

---

## 链接

首页所有 CTA 和图片链接必须真实可用。

检查：

```text
Shop Men
Shop Women
New
Packs
Learn More
Explore
Shop Now
Collection Card
Product Card
Content Page
```

禁止：

```html
href="#"
```

也不要 fallback 到首页。

链接应该指向真实：

```text
/collections/*
/products/*
/pages/*
/blogs/*
```

或 Shopify 动态 URL。

逐项核查最终目标资源是否真实存在、URL 是否返回预期内容，而不只是路径形状正确。原站文案与目标文章/页面年份不一致时，不得沿用旧 handle 伪装对应内容；未实现的内部目标应先按 `02-theme/pages/页面补齐.md` 补齐并读回，或如实报告阻塞，不计入已完成链接。

---

## Header / Sticky

根据 reference 检查首页 Header。

尤其确认：

* Announcement bar
* Logo row
* Main navigation
* Secondary navigation
* Sticky 行为
* 滚动后是否保留某些导航层
* Desktop / Mobile 是否不同

如果 reference 滚动时只保留第二栏和第三栏，则按照原页面实际 sticky 逻辑实现。

不要直接让整个 Header 全部 sticky。

---

## 图片和视频

图片优先通过 Shopify Theme Settings / Section Settings 管理。

不要在 Liquid 中大量写死外部图片 URL。

如果当前阶段 reference 中使用的是原站资源，可以先保持对应素材，但结构上要保证后续可在 Shopify 后台替换。

图片需要匹配原页面：

* aspect ratio
* object-fit
* object-position
* Desktop / Mobile crop

视频需要检查：

* autoplay
* muted
* loop
* playsinline
* poster
* Desktop / Mobile 行为

还要确认素材请求成功、在实际预览中解码并可见；视频首帧、加载失败、自动播放受限时使用对应 Desktop/Mobile poster 兜底。仅有 HTTP 200、`complete=true` 或正确 URL 不能证明画面与 reference 一致。

---

## Mobile

Mobile 首页必须单独参考 Mobile reference。

不要只把 Desktop：

```text
flex-direction: column
```

就算完成。

重点检查：

* Hero 高度
* 图片裁切
* 标题字号
* 页面 padding
* CTA 宽度
* Grid 列数
* Carousel
* Section 间距
* Header
* 导航
* 图片顺序
* 文案顺序

---

## 交互

如果原页面存在：

```text
Carousel
Slider
Tabs
Hover image
Mega menu
Dropdown
Accordion
Video controls
```

需要实现相同行为。

UI 控件使用正确语义：

```html
<button>
```

不要用：

```html
<a href="#">
```

代替按钮。

---

## 不要破坏已有页面

首页修改不能影响：

* Product Page
* Collection Page
* Cart
* Search
* Header
* Footer
* Product card

如果修改全局 CSS / JS，需要确认其他页面没有回归问题。

---

## 浏览器验收

完成后必须启动 Shopify Theme Preview，并使用浏览器 / Playwright 实际验收。

至少检查：

### Desktop

```text
1440px
```

### Mobile

```text
390 × 844
```

如果 reference 使用其他尺寸，以 reference 为准。

分别截图并与 source 对比：

* 页面首屏
* 页面中部
* 页面底部
* Mobile 首屏
* Mobile 中部

优先修复视觉误差最大的部分。

推荐顺序：

```text
1. 整体 Section 顺序
2. 页面宽度和比例
3. Hero
4. 图片尺寸
5. 字体
6. 间距
7. Grid
8. CTA
9. Sticky
10. 小细节
```

---

## 禁止事项

不要通过以下方式完成：

```text
写死大量首页内容
使用假商品
使用不存在的 Collection
href="#"
按钮跳首页
大量 absolute positioning 拼截图
只修 Desktop
只跑 theme check 不打开页面
为了视觉效果破坏动态 Shopify 数据
```

---

## 完成标准

只有同时满足以下条件才算完成：

* 首页 Section 顺序与 reference 基本一致
* Hero 与 reference 接近
* Desktop / Mobile 均完成校准
* 字体、间距、图片尺寸明显接近原页面
* 所有 Collection / Product 内容来自真实 Shopify 数据
* CTA 链接真实有效
* 不存在应跳转却仍然使用 `href="#"`
* Sticky Header 行为与原页面一致
* 所有交互正常
* 无明显横向溢出
* Header / Footer 没有回归
* Product / Collection 页面没有被首页修改破坏
* `shopify theme check` 通过，或剩余 warning 已说明
* 已通过实际浏览器完成验证
* 内容对照表中的每个未排除区块都有目标资源读回和 Draft 实际呈现证据；数据差异未解决时只能报告“主题层完成、首页内容未完成”
* 推送后按本次最新主题列表确认目标仍未发布、Live 未改变，并区分 Theme Check、Theme Dev、直接预览、Admin 数据与公开页面证据

完成后汇报：

```text
1. 修改了哪些文件
2. 首页新增或调整了哪些 Section
3. 哪些内容从写死改成了动态 Shopify 数据
4. 修复了哪些链接
5. Hero 做了哪些调整
6. Header / Sticky 做了哪些调整
7. Desktop / Mobile 分别做了哪些校准
8. 实际验证了哪些页面和 viewport
9. 当前仍存在什么与 reference 的差异
10. Store/App/权限/Publication、目标 Draft/当前 Live ID 与角色、数据差异归属、阻塞项及精确下一步
```

不要只回复“首页已完成”。
