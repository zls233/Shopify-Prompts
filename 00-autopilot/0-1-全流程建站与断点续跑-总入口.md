2. 默认 `EXECUTION_MODE=FAST`、`AUTOPILOT=ON`、`TARGET_THEME=DRAFT`。运行前需由操作者在 Codex 选择模型和推理等级；Prompt 不能自动切换模型。

## 自动运行决策
- 每阶段完成 P0 和适用核心交付（`completed_core` 或 `completed_full`）即可转下一阶段；P2 和非阻断 P1 持久化到 deferred，不重复检查已有有效证据。不得把上传/样本成功伪装为全量数据完成。
- 对网络限流/瞬时失败按 Retry-After、退避做有限重试，重试前先检查是否已成功；对有效代码问题先定位根因、定向修复并复测。**最多两轮同根因有进展的自动修复**；没有证据证明有进展时立即停止该问题的重试。
- 对真实权限缺失、等待登录/2FA/CAPTCHA、确实不可取得的关键技术输入、无法自行处理的权限/认证障碍、共享资源修改超出已授予权限等，记录明确 `blocked`。继续完成与其独立的本地工作；依赖该问题的阶段不得假装通过或越权跳过。列出最小人工操作和精确恢复入口。
- 任一阶段存在会污染下游的 P0/关键缺口（如未导入商品却开始宣称 PDP 已验收），暂停依赖链，不盲跑后续步骤。非关键 P2 可记录后继续。
- 已完成阶段恢复时对比输入版本、店铺资源实际状态、Theme ID/文件与预期数据差集；有效才跳过。导入/价格修改必须幂等，不重复折扣、重复导入或覆盖别的店铺。
- 用简洁阶段状态汇报进度，但**不等待用户再发送下一步**；把每阶段实际执行日志、证据及下一步记录到项目。保留工作分支和可回滚的资源映射。
- 产品、集合、菜单、Pages、Files 是可能影响 Live 的共享数据；在开始任何操作前按子 Prompt 核对资源目标和权限，不把 Draft 当作共享资源隔离。
- **安全边界**：AUTOPILOT/运行0-1 不构成 Live 发布、关闭 Private Mode、修改商家地址、支付配置、下单或付款的新授权；这些必须已有独立且有效的授权。无此授权时完成 Draft 可完成部分，报告 Live 和公开购物链路为 blocked/not_run。

## 结束条件与报告
完整执行到 6-1 后输出精简摘要：各阶段核心状态、商品/库存实际核验数量、典型 Desktop/Mobile 购物链路、分类数据检查覆盖、Footer 八链接、真实 blocker 与 deferred 总结；重要信息链接到当前项目已有证据，不复制整份审计明细。仅核心交付通过可写「Draft 核心完成」，P2 等 deferred 独立列出；若未完整 Live/公开验证必须单独注明，不可把 `completed_core` 伪称 `completed_full`。
