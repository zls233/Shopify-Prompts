# 0-1 AUTOPILOT：从初始化到 QA 的全流程自动执行

你现在是 Shopify 建站流水线总控。**一次指令连续运行现有 FAST 六阶段，不要只输出计划、伪造执行记录，或要求用户逐步发送 1-1 至 6-1。** 严格按真实仓库文件执行，不复制或重新解释子 Prompt。

## 初始化
1. 读取 `AGENTS.md`、`PROMPT_ROUTING.md`、`EXECUTION_RULES.md`、`05-customization/5-2-功能削减.md` 和项目 `PROJECT_MEMORY.md`（存在时）。核对当前项目路径、Git remote、参考站 URL、目标 Shopify `*.myshopify.com`、Partner/CLI/App 权限、Draft/Live 角色以及已明确的项目例外。缺少必要输入时优先从当前项目与已有环境取证，不猜测商店或使用历史项目值。
2. 默认 `EXECUTION_MODE=FAST`、`AUTOPILOT=ON`、`TARGET_THEME=DRAFT`。运行前需由操作者在 Codex 选择模型和推理等级；Prompt 不能自动切换模型。
3. 维护当前项目 `agent-evidence/autopilot-state.json`，记录 store、reference、branch、阶段 ID、开始/结束时间、输入哈希/版本、远端读回证据、阶段状态 `pending/in_progress/verified/blocked/failed/excluded`、未解决差集和恢复位置。更新 `PROJECT_MEMORY.md`，不保存任何凭据。不要将状态文件中的完成标记当作远端真实完成证据。

## 固定阶段序列（不可按编号大小重排）
`1-1 → 2-1 → 4-1 → 3-1 → 5-1 → 6-1`

依次读取并执行：
1. `01-project/1-1-创建项目.md`：初始化并确认授权；需要时按现有 1-2 规则。
2. `02-reference/2-1-页面爬取.md`：参考站、真实素材和 favicon 采集与验证。
3. `04-catalog/4-1-爬取商品SKU.md`：在同一阶段完成 4-2 清洗、4-3 导入、4-4 集合/菜单及全量对账。
4. `03-theme/3-1-开始复刻.md`：必要页面、原站素材、真实商品、响应式、Draft 远端浏览器 QA；失败时调用现有专项修复。
5. `05-customization/5-1-打折.md`：按现有授权和范围执行价格策略、5-2 功能削减、5-3 Cookie、条件 5-4。不得因免邮公告去更改真实 Shipping 规则。
6. `06-qa/6-1-交付评估.md`：包含 `06-qa/6-5-全站入口NotFound扫描与修复.md` 的全站入口核验、根因集中修复和复测；仅已有针对该店/版本的明确授权才执行 6-2 发布及 6-3 开放；公开可访问后按 6-4 测试真实 Cart → Checkout 到界面为止，不支付、不下单。

## 自动运行决策
- 每阶段读取实际子 Prompt、实施、读回、完成验收，再转下一阶段；不要把上传、脚本返回成功、样本通过或静态检查通过直接当成 `verified`。
- 对网络限流/瞬时失败按 Retry-After、退避做有限重试，重试前先检查是否已成功；对有效代码问题先定位根因、定向修复并复测。**最多三轮同根因自动修复**；没有证据证明有进展时立即停止该问题的重试。
- 对真实权限缺失、等待登录/2FA/CAPTCHA、缺少必要且无法取得的输入、无批准政策正文、共享资源修改超出授权等，记录明确 `blocked`。继续完成与其独立的本地工作；依赖该问题的阶段不得假装通过或越权跳过。列出最小人工操作和精确恢复入口。
- 任一阶段存在会污染下游的 P0/关键缺口（如未导入商品却开始宣称 PDP 已验收），暂停依赖链，不盲跑后续步骤。非关键 P2 可记录后继续。
- 已完成阶段恢复时对比输入版本、店铺资源实际状态、Theme ID/文件与预期数据差集；有效才跳过。导入/价格修改必须幂等，不重复折扣、重复导入或覆盖别的店铺。
- 用简洁阶段状态汇报进度，但**不等待用户再发送下一步**；把每阶段实际执行日志、证据及下一步记录到项目。保留工作分支和可回滚的资源映射。
- 产品、集合、菜单、Pages、Files 是可能影响 Live 的共享数据；在开始任何操作前按子 Prompt 核对资源目标和权限，不把 Draft 当作共享资源隔离。
- **安全边界**：AUTOPILOT/运行0-1 不构成 Live 发布、关闭 Private Mode、修改商家地址、支付配置、下单或付款的新授权；这些必须已有独立且有效的授权。无此授权时完成 Draft 可完成部分，报告 Live 和公开购物链路为 blocked/not_run。

## 结束条件与报告
完整执行到 6-1 后分别报告：阶段完成情况、全量产品/变体与 Collections 差集、目标 Draft Theme ID 及远端读回、Favicon、桌面/移动视觉、Footer 八链、全站死链扫描/修复数量、Cart→Checkout 状态、Live/公开状态、剩余 P0/P1/P2、所有 blocked 项及对应的最小恢复操作。只有所有范围内、可验收层均实际通过时才称全部交付完成。若只有 Draft 完成，请明确写「Draft 阶段完成；Live/公开验收未完成」。
