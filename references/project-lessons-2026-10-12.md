# 最近五个项目的更新依据

整理日期：2026-10-12。按 Codex 中最近有聊天活动的项目去重选取：Petal & Pup、Faherty、Corridor、The Ordinary、Dagne Dover。Typology 不在本次最近五个项目中。

本记录只保存可复用的用户要求、已报告的问题和规则改动，不保存凭据、店铺/App/Theme GID，也不把聊天中的历史成功报告当作当前远端事实。当前店铺状态仍须在项目执行时重新读回。

| 项目 | 聊天中的要求/问题 | 固化到 Prompt 的做法 |
|---|---|---|
| Petal & Pup | `4-1` 曾被误当发布前验收，页面编号也曾对应错误任务；用户已明确纠正并要求读取实际 Prompt | 完整编号路由、启动时记录文件与任务，承接时不复用旧编号解释 |
| Petal & Pup | 分类数量检查后仍发现漏分/交叉归属；颜色和尺码筛选需要真实数据及后台配置；最终更新仅在 Development | 全入口成员差集、非互斥分类、筛选字段/后台/Theme 分层排查；逐次记录 Development/Live 和共享数据 |
| Petal & Pup | Development 不能直接发布，实际通过 unpublished 候选发布；用户要求多项定制列 Todo 逐项保证效果 | 开发主题候选转换与重新核验；多任务进度/恢复清单 |
| Faherty | 用户多次要求首页后逐个剩余页面原站对照；早期空商品/文章目录仍被描述为已完成 | 页面/区块清单、真实字体素材、模板与资源分开验收；空目录不证明商品行为 |
| Faherty | 后续要求全部分类成员正确，以及顶栏/底栏在各屏幕宽度适配；出现购物车 404、单图悬停空白和 Quick Shop 遮图 | 全分类巡检、真实购物路径、单图/多图卡片；公共组件和实际断点复查 |
| Corridor | 用户指出只有几个样本商品，全量商品导入没有执行完；后续仍有特殊商品跳过 | 样本后继续全量、逐项清单覆盖、失败恢复；明确排除和原生功能缺口，不凑商品数量 |
| Corridor | 全站图片拉伸、卡片显示错误，首页缺三张分类卡；About/Journal/Stores/PLP/PDP 均需修复 | 自然比例/裁切分开、卡片/PDP/集合上下文媒体映射、首页整行区块数量检查 |
| Corridor | 用户明确不要 SunBrowser，已有自己的 Partners 连接；远端视觉仍受浏览器连接限制；分类仍是手动集合 | 复用授权、拆分浏览器/CLI/数据身份故障；如实报告远端视觉阻塞与自动分类未完成 |
| The Ordinary | 用户检查是否能直接上传完整店铺；旧脚本绑定另一店铺，输入产物缺失，商品 Active/发布状态与历史报告冲突 | 可上传 Theme/原生数据/可交付分别判断；干净 checkout 与换店铺映射检查，当前状态实时读回 |
| The Ordinary | 用户要求进入顶栏每个分类，与原站匹配成员/UI；不要求商品排列完全一致；Admin 登录未解除访客密码页 | 全分类成员对账与分类 UI 独立核验；尊重顺序范围；认证预览和公开访问分别记录 |
| Dagne Dover | 多次“全部完成”报告仍有因空目录而 blocked 的 PDP/集合/文章检查；后续要求首页后逐页继续、修复分类与移动布局 | blocked 不计通过，真实资源与交互验收，逐页闭环和完整分类巡检 |
| 五个项目共性 | 用户重复“继续完成”“重试推送”，要求用现有授权推进；文件上传/读回不能等同完整视觉与商品验收 | 保留授权、检查点续做、有限重试、验证层分别报告并更新项目记忆 |
